# HISR MVP Spec v0.1

## 产品定位

HISR 面向对现实处境、为人处世或未来选择感到迷茫的人。用户通过描述问题，获得来自历史案例、哲学思想和文学作品的多角度参照，从而形成自己的判断。

> 历史提供参照，哲学提供解释，文学提供共鸣。

## 核心原则

- 文史哲不分家。
- 帮助用户看见更多可能性，不替用户作决定。
- 明确区分事实、解释与推测。
- 历史案例和文学作品应提供基本出处，不伪造引用。
- 不替代医疗、法律、金融或心理危机服务。

## 核心用户流程

1. 用户描述现实困惑。
2. 用户选择问题类型：关系、工作、学习、人生选择、价值观冲突或其他。
3. 系统提炼事件背景、核心冲突、情绪和用户重视的价值。
4. 系统提供历史参照、哲学视角和文学映照。
5. 系统比较两到三个可能方向及其收益与代价。
6. 系统提出值得继续思考的问题，允许用户追问。

## 回答结构

1. 我理解到的处境
2. 历史中的相似处境
3. 哲学视角
4. 文学中的映照
5. 相似点与不同点
6. 可能方向、收益与代价
7. 继续思考的问题

## MVP 必须完成

- 用户输入问题并选择类型
- 调用 LLM API
- 返回并展示结构化回答
- 覆盖历史、哲学、文学三个维度
- 显示免责声明与安全提示
- 保存最近咨询记录
- 支持继续追问

## 首版暂不完成

- 复杂账号与权限系统
- 社交功能
- 自动抓取互联网内容
- 完整向量数据库和复杂推荐系统
- 移动端原生应用
- Docker 部署

## 建议页面

- 首页：品牌介绍、问题输入、问题类型、最近咨询
- 结果页：结构化分析、文史哲卡片、方向比较、追问入口
- 历史记录页：问题标题、时间、问题与回答

## 建议技术路线

- 前端：Next.js、React、TypeScript、Tailwind CSS
- 后端首版：Next.js API Routes
- 数据首版：SQLite 或本地 JSON
- 知识内容：人工整理历史案例、哲学概念和文学作品
- 后续：embeddings + vector database + RAG

## MVP 验收标准

- 用户能在一分钟内提交问题。
- 回答包含历史、哲学、文学三个维度。
- 至少提供两个不同方向及其代价。
- 不直接替用户作决定。
- 关键引用具有基本出处。
- 桌面浏览器可以正常完成一次完整咨询。
